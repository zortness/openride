# Working on OpenRide

Read docs/milestones.md for status and the relevant milestone/progress document
before implementing. Windows desktop is the current supported target. Original
code is MIT; external map data and dependencies have separate licenses.

## Source and private data

- Keep personal activities in import/, generated route exports in export/, and
  captures, downloaded sources, logs and scratch work in local/. These are ignored.
- Never commit ANT network keys, real activity journals, downloaded map/imagery
  packages, binaries or credentials. Keep synthetic regression fixtures in source.
- Source scenery/editor scripts live in apps/scenery-preview. The directories
  apps/rider/scenery and apps/rider/editor are generated by
  tools/sync-scenery-runtime.ps1; edit the originals.
- Preserve original activity files. A first import pass inspects source variants,
  timestamps, units, gaps and diagnostics before selecting a route subsection.
  Route geographic data is still personal even when biometrics are removed.

## Build and validation

- See docs/development.md and tools/README.md for commands. Use locked Cargo
  dependencies. Run tools/build.ps1 before launching a fresh Godot checkout;
  it generates runtime sources and copies native components.
- Discover Python/Godot on PATH or accept explicit executable overrides. Do not
  hardcode a contributor's home directory or choose Thonny's bundled Python.
- Automated Godot checks must use an isolated APPDATA under local/godot-appdata;
  never alter the user's real sessions/preferences. Set this per process/session.
- Use hidden, redirected, bounded processes for automated Windows GUI tests.
  Inspect logs and exit status. Godot release assertions may be stripped: use
  explicit failure exits for exported-app acceptance checks.
- Default checks: cargo test --workspace --locked --offline and
  python -m unittest discover -s tools/tests. Ignored private/hardware tests require
  their prerequisites and must not be enabled wholesale.
- Hardware commands require the user's applicable authorization and readiness.
  A fake worker proves software behavior, not physical resistance or safe cleanup.
- Read fresh verification output before completion claims. Preserve deferred
  endurance/dropout gates rather than silently marking them complete.

## Architecture

Keep device I/O and recording independent of rendering. Preserve selected source
identity, distinguish zero from missing, and maintain one trainer control owner.
Keep control targets distinct from actual acknowledgments and route geography.
See docs/tooling-roadmap.md for proposed native authoring migration and agent skills.
